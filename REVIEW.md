# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (Line 72) | Returns static `{"status": "ok"}` without pinging MongoDB; fails to return 503 when the database is unavailable. | Stopping MongoDB service and calling `GET /health` returned HTTP 200 instead of HTTP 503. | Wrapped `client.admin.command("ping")` in a try/except block that raises `HTTPException(503)` if MongoDB fails to respond. |
| 2 | `compute_late_minutes` (Line 33) | Naive datetime replacement ignores time zones; does not enforce strict $> 10$ minute cutoff (grace period); fails on overnight shifts. | Punching in at 09:40:00 for a 09:30 shift returned 10 late minutes instead of 0; timezone mismatch caused erratic calculations. | Converted instants to IST, constructed shift start datetime with IST timezone on the attendance date, and checked `diff_sec > 600` before taking floor integer minutes. |
| 3 | `compute_work_hours` (Line 40) | Uses standard Python `round()`, which performs Banker's Rounding (round-half-to-even) rather than Round-Half-Up required by R4/R8. | A work duration such as 8.125 hours rounded down to 8.12 instead of rounding up to 8.13. | Created `round_half_up()` utility using Python's `decimal.Decimal` with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` (Line 44) | Returns `max(0, minutes)` without enforcing the 30-minute minimum threshold (R3); fails across midnight for overnight shifts due to naive date calculation. | Punching out 15 minutes after shift end returned 15 overtime minutes instead of 0; overnight shifts computed negative or incorrect values. | Added overnight shift check (`shift_end <= shift_start`) to project shift end to next calendar day, and only credited overtime if difference $\ge 1800$ seconds (30 minutes). |
| 5 | `create_employee` (Line 78) | Check-then-insert race condition (`find_one` followed by `insert_one`); missing validation for duplicate `emp_code`, `shift_start == shift_end`, and `emp_code` regex; naive `datetime.now()` for `created_at`. | Sending concurrent duplicate employee creations created duplicate records or crashed; invalid employee codes were accepted; `created_at` was not formatted as epoch milliseconds. | Added unique index on `emp_code`, handled `DuplicateKeyError` returning 409, enforced Pydantic model validation, and serialized `created_at` as epoch ms. |
| 6 | `list_employees` (Line 89) | `skip = page * page_size` skipped page 1 entirely; `total = count_documents({})` ignored the `department` filter; missing sorting by `emp_code` ascending. | Requesting `page=1` returned items starting from index 20; filtering by department returned total collection size rather than filtered count. | Fixed pagination offset to `(page - 1) * page_size`, passed filter `q` to `count_documents(q)`, added `.sort("emp_code", 1)`, and formatted documents. |
| 7 | `punch_in` (Line 99) | Check-then-insert race condition; naive local time conversion; missing overnight shift date calculation (R1); crashes with 500 on missing employee; injects invalid `"id"` field into response. | Concurrent punch-ins created duplicate records; overnight shift punches at 05:45 IST recorded the wrong date; missing employee crashed with 500 instead of 404; response schema violated. | Added compound unique index `(emp_code, date)`, verified employee existence returning 404, implemented R1 date calculation, handled `DuplicateKeyError` with 409, and removed extraneous fields. |
| 8 | `list_attendance` (Line 124) | Fetched all records into Python memory with `list(db.attendance_logs.find(q))` and sorted in Python, failing on 100k records; injected `"id"` field; lacked `date_from > date_to` validation. | High memory consumption and latency on large datasets; calling with `date_from > date_to` failed to return 422. | Replaced in-memory operations with database-level sorting `.sort([("date", -1), ("emp_code", 1)])` and pagination (`.skip()`, `.limit()`), validated date ranges, and formatted instants as epoch ms. |
| 9 | Startup Indexes (Entire file) | No MongoDB indexes created at application startup. | Database performed slow collection scans (`COLLSCAN`) and could not enforce uniqueness constraints under concurrent traffic. | Created an `init_db()` function called during FastAPI `lifespan` to idempotently build all required single-field and compound indexes. |

### Examined and Decided Not Defective
- **Spec / Framework Versioning:** `app.version="2.0.0"` in FastAPI matches OpenAPI 3.0.3 versioning.
- **Pydantic Validation:** Using Pydantic models for incoming payloads is standard and correctly maps 422 Unprocessable Entity responses.
